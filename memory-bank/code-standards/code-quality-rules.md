Не превышать уровень вложенности 2–3 в одном фрагменте кода.

Использовать ранний выход из функции (return, ? для обработки ошибок) вместо глубоких вложенных условий.

Вынести вложенную логику в отдельные функции, чтобы уменьшить вложенность в основной функции.

Применять конструкции типа match и комбинаторы (map, and_then) для замены вложенных if-else.

Избегать вложенных циклов и условий внутри друг друга, если возможна их замена на последовательные шаги.

Использовать логические операторы (&&, ||) для объединения условий вместо вложенных if.

Следить за читаемостью: если код становится трудно воспринимаемым из-за вложений, проводить рефакторинг.

## Переиспользуемые утилиты фронта

`crates/frontend/src/shared/` — единственный источник истины для переиспользуемых утилит: API (`api_utils.rs`), дата/время (`date_utils.rs`), форматирование чисел (`list_utils.rs`), браузерные операции (`clipboard.rs`, `export.rs`), UI-хелперы (`components/`).

Не реализовывать локальную копию того, что уже есть в `shared`; новую утилиту сначала добавлять в `shared`, потом использовать. Исключение — логика, которая действительно принадлежит конкретному домену.

Вместо флагов-параметров делать отдельные варианты функции: `format_datetime()` / `format_datetime_space()`, а не `format_datetime(s, use_space: bool)`.

Историю появления правила (дедупликация 17 копий `api_base()` и 6 копий `format_datetime()`) см. в `memory-bank/_archive/decisions/shared-utilities-organization.md`.
