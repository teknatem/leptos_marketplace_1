# Проверка и исправление p916

Используй этот workflow только для `p916_mp_sales_funnel_turnovers`. Диагностика read-only;
загрузка и перепроведение доступны только `coordinator_admin` после подтверждения пользователя.

## Два хода

1. Вызови `prepare_funnel_repair` с точным периодом и кабинетами. Пустой список кабинетов
   означает все подключения WB/YM.
2. Покажи `preview_text`, список `repair_spec.actions`, ограничения и результаты QC. Разделяй:
   `healthy`, `rebuildable`, `reloadable`, `manual_review` и `impossible`.
3. Остановись и дождись следующего сообщения пользователя. Согласие должно относиться ко всему
   показанному плану.
4. После согласия вызови `execute_funnel_repair` с неизменёнными `repair_spec`, `payload_hash` и
   `confirm=true`. Любая правка периода, кабинетов или действий требует нового prepare.
5. Вызывай `get_funnel_repair_status`, пока статус `running`. Успех определяется только post-check.

## Что выполняется

- WB: `a015` → `a012` → `wb_advert_stats` → исторический `a036` для завершённых дат;
  оперативный `a036` запускается только для текущей даты. История длиннее 365 дней делится
  на безопасные интервалы.
- YM: `a013` → `a016` → `a041`; за пределами максимального окна 400 дней marketing-stage
  восстановить нельзя.
- После загрузки выполняется `u508` по тому же периоду и кабинетам, затем QC-007/008/009.
- `projection_extra` автоматически не удаляется. Органические показы WB не восстанавливаются из
  `a040`; это `N/A`, а не дефект.

## Финальный отчёт

Назови отдельно: найденные проблемы; выполненные загрузки и перепроведение; исправленные
нарушения; оставшиеся нарушения; объективные ограничения; точный период и кабинеты, для которых
post-check подтвердил корректность. `completed_with_limitations` не называй полным успехом.
